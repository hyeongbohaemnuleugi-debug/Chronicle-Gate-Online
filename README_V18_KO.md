# Chronicle Gate v18 설치와 플레이

> v18.1 업데이트를 적용한다면 먼저 `PATCH_NOTES_V18_1.md`를 읽어 주세요. 아래는 v18부터 이어지는 기본 플레이 안내입니다.

이번 수정의 중심은 **내가 고른 행동이 다음 문장과 다음 장소를 여는 느낌**입니다. 소개문부터 구체적으로 고치고, 결과문과 다음 장면 사이의 이동을 보강합니다. 본문은 짧은 문단으로 읽고, 판정 계산과 상황 정리는 필요할 때 펼칩니다.

## 1. 어느 ZIP을 적용하나요?

| 파일 이름에 들어 있는 표시 | 적용할 곳 |
|---|---|
| `FROM_v17_Changed_Files` | 바로 전 v17 패치를 적용한 프로젝트. v17 이후 바뀐 파일만 포함합니다. |
| `Cumulative_GitHub_PATCH` | 처음 제공한 `Chronicle-Gate-Online-main(2).zip`의 프로젝트, 또는 이전 패치 적용 여부가 불확실한 프로젝트. 원본 이후의 누적 변경 파일입니다. |

맞는 ZIP **하나만** 사용합니다. 두 파일 모두 GitHub 저장소 전체를 대체하는 독립 프로젝트가 아닙니다. 압축 안의 경로를 기존 저장소 루트에 겹쳐 적용합니다.

1. 현재 코드와 중요한 진행의 JSON 저장을 백업합니다.
2. 선택한 ZIP을 완전히 풉니다.
3. 안의 `public/`, `game-server/`, `scripts/`, `tests-v18/`와 루트 파일들을 기존 프로젝트의 같은 경로에 복사합니다.
4. GitHub Desktop 등에서 추가·변경 목록을 확인하고 커밋합니다. `public/public/`처럼 중첩하지 않습니다.
5. 아래 명령으로 확인하고 실행합니다.

```bash
npm ci
npm run verify
npm start
```

Node.js 22 또는 24를 사용합니다. 운영 빌드가 개발 도구를 설치하지 않는 구성이라면 `npm ci --omit=dev && npm run verify`가 가능합니다. 시작 명령은 `npm start`입니다. 배포 후 `/health`의 `version: "18.1.0"`과 화면 하단 v18을 확인합니다.

`FILES_CHANGED_V18.txt`에 파일 목록, `V18_PATCH_MANIFEST.json`에 패치 기준·각 파일의 SHA-256이 있습니다. 개인 `.env`, 실제 방 저장, 계정 토큰은 포함하지 않습니다. `COPYPASTE/index.html.txt`는 `public/index.html`과 같은 내용의 복사용 파일입니다. 이 파일 하나만으로 전체 업데이트가 되지는 않습니다.

## 2. 먼저 친구들과 플레이하기

**같은 기기에서 1–4명:** 적용한 프로젝트에서 다음 명령을 실행한 뒤 `http://127.0.0.1:4173/`에 접속합니다. npm 패키지 설치 없이 Node.js 기본 기능으로 실행됩니다.

```bash
node scripts/offline-server.mjs
```

`PLAY_OFFLINE.html`로 여는 번들도 있습니다. `public/offline.html`과 `public/game/`의 기존 이미지·음원이 함께 있어야 합니다. 직접 파일 실행은 브라우저 설정에 영향을 받으므로 로컬 서버 실행을 우선 안내합니다. 같은 화면을 차례로 쓰는 방식입니다.

**각자 기기로 접속:** 패치를 적용한 Node 서버에서 방장이 이야기와 직업을 고르고 방을 엽니다. 친구들은 6자리 방 코드로 들어옵니다. 최대 네 명이며, 모두 준비되면 방장이 시작합니다.

## 3. 이야기를 읽는 순서

**내 선택의 결과 → 그 일로 도착한 장면 → 지금 고를 행동** 순서입니다.

승강장에서 객실로 이어질 때는 단순히 장소 제목만 바꾸지 않고, 왜 열차에 타며 누가 어떻게 문을 넘는지 결과문에 담습니다. 실패했다면 실패가 만든 우회로와 대가가 이어집니다. 이동하지 않는 장면도 인물이 대화를 끝내거나 상황이 바뀌는 계기를 남깁니다.

안전한 관찰을 하더라도 직전 선택이나 전투 결과를 본문 앞에서 계속 읽습니다. 관찰 내용은 「살펴본 것」에 따로 놓습니다. 오래된 저장에 자세한 결과가 없으면 실제로 남아 있는 도착 기록을 보여 주며, 사라진 과거를 새로 지어내지는 않습니다.

「장면 정리」에는 현재 문제와 목표가, 「판정과 변화」에는 주사위 계산과 아이템·자원 변화가 있습니다. 중요한 생명력·사망 위험·전투 행동은 계속 드러납니다. 긴 후일담은 「이 선택이 남긴 흔적」을 펼쳐 전문을 읽습니다.

## 4. 혼자와 여럿의 이야기

일곱 이야기 모두 초반과 후반의 중요한 장면에 1인 전용 선택 두 개, 함께할 때의 선택 두 개가 있습니다. 각각 네 주사위 결과를 따로 작성했습니다. 혼자일 때는 자신의 위험과 약속, 여럿일 때는 동료를 위해 마련하는 길·증언·도움이 중심입니다. 성공으로 남긴 약속이나 표지는 실제 플래그로 저장되고 이후 장면과 결말이 기억합니다.

시작 도입과 해당 갈림길의 본문도 인원에 맞습니다. 기존 선택을 함께 제공하되 한 화면에 보이는 선택은 최대 네 개입니다. 동료의 의견을 자동으로 결정하거나 다른 사람의 비밀을 대신 공개하는 방식은 사용하지 않습니다. 의논은 대화창으로 하고 실제 차례의 인물이 선택합니다.

이야기의 인원 기준은 **시작할 때 참여한 인원**입니다. 네 명으로 시작해 한 명이 남아도 함께한 여정을 유지합니다. 실제 협력이 필요한 선택은 살아 있는 동료가 있을 때만 열리며, 혼자 남은 인물이 계속 진행할 기본 경로도 남습니다. 연결이 끊겨도 이야기가 갑자기 1인용으로 바뀌지 않습니다.

각 이야기에 일반 결말 세 가지와 전원 사망 결말이 있고, 그 안에서 실제 선택·직업·생존·희생·귀환에 따른 문장이 달라집니다. 조건부 후일담과 별도 결말 제목의 수는 구분합니다.

## 5. 주사위·전투·아이템

| 결과 | 기준 |
|---|---|
| 대성공 | 주사위 자체가 20 |
| 성공 | 자연 1·20 이외에서 `D20 + 보너스 ≥ 목표` |
| 실패 | 자연 1·20 이외에서 `D20 + 보너스 < 목표` |
| 대실패 | 주사위 자체가 1 |

안전한 관찰과 일부 확정 선택에는 주사위를 쓰지 않습니다. 위험 선택은 네 결과의 정보·부상·위기·경로 등이 다릅니다. 판정 창의 상세 설명에서 실제 결과와 확률을 확인할 수 있습니다. 직접 입력하는 자유 행동과 능력치 굴림은 없습니다.

직업은 이야기마다 네 개씩, 총 28개입니다. 각자 고정 능력치, 기본 공격 하나, 전투마다 한 번 쓰는 능력 하나를 가집니다. 이야기마다 일반 결말까지 가는 길에 상황과 연결된 전투가 한 번 있습니다.

생명은 최대 3이고 0이면 사망합니다. 살아 있는 동료가 귀환 장소에 도착하면 부활을 시도할 수 있습니다. 기본 비용은 운명 조각 1개와 위기 2칸이며, 대성공은 생명 3, 성공은 생명 2로 돌아옵니다. 실패는 위기 1, 대실패는 위기 2가 추가됩니다. 같은 장소에서 같은 인물에게 한 번, 성공한 부활은 인물당 한 번입니다. 전원 사망하면 즉시 조기 결말입니다. 1인 플레이에서도 사망 뒤 자동 부활하지 않습니다.

단서는 알아낸 사실, 가방은 실제 챙긴 물건입니다. 소모품은 실행 전 안내한 대로 사용되며, 이미 쓴 물건은 저장을 다시 불러와도 생기지 않습니다. 물건을 놓쳤을 때 이용할 다른 선택도 남습니다. 상세 전투 수치와 직업은 `CLASS_GUIDE_V18.md`에 있습니다.

## 6. 우리의 연대기

「연대기」에서 실제로 한 선택을 시간순으로 읽습니다. 일반 공격과 반복 관찰은 「전체 플레이 기록」에 있고, 선택·부활 시도·전투의 결말·전투 중 사망은 연대기에 남습니다.

**연대기 TXT**는 읽기 위한 기록입니다. 실제 도입, 실제 선택의 결과, 현재 장면 또는 마지막 후일담을 담습니다. **진행 저장 JSON**은 게임을 이어하기 위한 저장입니다. 서로 다른 용도이며 TXT로 게임 상태를 복구하지 않습니다.

연대기는 의미 있는 최근 사건 40개까지 보관합니다. 옛 저장에서 잃어버린 기록이나 한도 때문에 빠진 기록이 있으면 부분 기록이라고 표시합니다. 긴 개인 후일담은 TXT에도 전문을 담습니다. 개인 비밀 카드·접속 토큰·인증 정보는 TXT에 넣지 않습니다.

## 7. 기존 저장과 서버

v14–v17 저장을 읽으며 v18도 내부 스키마 17을 유지합니다. 내보내기 이름은 `chronicle-gate-v18`입니다. 이전 브라우저 저장 키와 디스크 경로를 이어받습니다. v12·v13의 다른 시나리오 저장은 변환하지 않습니다.

새로 쓴 첫 장과 1인/함께하는 선택은 새 이야기에서 읽는 것을 권장합니다. 이미 지나간 선택은 다시 판정하지 않습니다. 옛 기록에서 복구할 수 있는 실제 선택만 새 연대기에 옮깁니다.

기본 서버는 Supabase나 외부 AI API를 호출하지 않는 Node.js + Socket.IO 구조입니다. 서버 메모리 또는 지정한 영구 디스크에 방을 저장합니다. 방 32개, 방당 최대 네 명, 방 저장 256KiB, 채팅 최근 30개·30분 등의 기존 제한을 유지합니다. 운영 모드에서 디스크를 지정하지 않으면 재시작 시 방이 없어질 수 있으므로 방장 자동 복구 사본과 JSON 저장을 이용합니다.

영구 디스크 경로는 `CHRONICLE_V18_DATA_DIR`을 사용할 수 있습니다. 기존 V17/V16/V15/V14 변수도 지원하며, 실제 기존 저장 폴더를 유지하면 됩니다. 자세한 설정은 `SERVER_AND_STORAGE_V18.md`에 있습니다.

## 8. 그림·음악·검증 범위

이번 수정에서 v17의 WebP 7개에 담긴 장면 28컷, BGM 35개·효과음 11개의 실제 파일은 그대로 유지합니다. 코드·스타일은 캐시 버전 18000, 미디어는 17000입니다. 사운드는 직접 켤 때만 재생하며 같은 BGM을 매 행동마다 다시 시작하지 않습니다.

파일 용량과 해시 비교는 `RESOURCE_REPORT_V18.json`, 수행한 검사와 한계는 `VALIDATION_V18.md`에 있습니다. 실제 브라우저의 시각·오디오 재생 검증 및 사용자의 운영 서버 성능 측정은 별도로 수행하지 못했습니다.

왈도쿤·여까가 함께한 공개 TRPG 영상의 제목·소개는 확인했습니다. 하지만 영상 재생과 자막 본문은 가져오지 못해 실제 진행 장면을 시청·분석했다고 주장하지 않습니다. 이번 분기와 연결은 게임을 위해 직접 집필한 설계입니다. 조사한 원본과 확인 범위는 `STORY_GUIDE_V18.md`에 기록합니다.

## 9. 파일을 직접 수정한다면

| 바꿀 내용 | 파일 |
|---|---|
| 본문·소개·선택·이동 결과·인원별 차이 | `public/game/campaigns/`의 일곱 이야기 파일 |
| 고정 직업·공격·기술·전투 도입 | `public/game/campaigns/combat-data.js` |
| 장면·인원 조건·아이템·사망·부활·저장 | `public/game/engine.js` |
| 실제 선택의 연대기·TXT 내용 | `public/game/narrative.js` |
| 읽는 순서·관찰·화면 | `public/game/app.js`, `public/game/styles.css` |
| 온라인 방과 서버 판정 | `game-server/table-service.js` |
| 파일 응답·캐시 | `game-server/http-service.js` |
| 자동 검사 | `tests-v18/`, `scripts/qa-v18.mjs` |

`tests-v18`는 일반 테스트 폴더입니다. 게임 플레이 폴더가 아니며 검사 명령이 해당 이름을 사용합니다.

```bash
npm run verify
npm run test:ui
npm run test:integration
npm run test:routes
npm run build:offline
```

소스를 고쳤다면 마지막에 오프라인 번들을 다시 빌드합니다. `COPYPASTE/index.html.txt`도 `public/index.html`과 같게 갱신합니다.
