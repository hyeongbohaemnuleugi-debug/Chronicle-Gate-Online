# Chronicle Gate v17 — 선택의 결과가 이어지는 이야기

v17은 **본문의 이해도와 분기의 연결**을 중심으로 고친 누적 수정 패치입니다. 일곱 이야기의 장면 도입·목표·위험을 다시 쓰고, 위험한 선택마다 대성공·성공·실패·대실패의 결과를 따로 집필했습니다. 자유 행동 입력은 화면과 엔진에서 제거했습니다. 플레이어끼리 의논하는 대화창은 그대로 사용할 수 있습니다.

단순히 결과 제목만 네 가지로 나누지 않았습니다. 같은 행동도 판정에 따라 얻는 정보·물건, 인물의 협력, 부상, 위기, 이어지는 경로가 달라집니다. 같은 장소에 도착하는 분기도 그곳까지 오며 바뀐 상태를 이어받습니다. 장면은 무한히 생성되지 않으며, 미리 작성한 사건과 조건부 문장으로 진행됩니다.

## 1. GitHub에 적용하기

이 ZIP은 사용자가 제공한 `Chronicle-Gate-Online-main(2).zip`을 기준으로 만든 **누적 변경 파일 묶음**입니다. 원본 또는 v14·v15·v16 패치를 적용한 저장소의 같은 경로에 덮어씁니다. 온라인 서버 전체를 새로 담은 독립 저장소가 아닙니다.

1. 현재 저장소와 진행 중인 게임의 JSON 저장을 백업합니다.
2. ZIP을 완전히 풉니다. 압축 루트에 `server.js`, `package.json`, `public/`, `game-server/`, `tests-v17/`이 있습니다.
3. **압축 안의 파일들을 기존 저장소 루트의 같은 경로에 복사합니다.** ZIP 자체를 업로드하거나 `public/public/`처럼 폴더를 중첩하지 않습니다. `index.html` 하나만 교체하면 동작하지 않습니다.
4. 추가·수정 파일, `package-lock.json`, 그림·음원을 함께 커밋합니다. GitHub Desktop에서는 저장소 폴더에 복사한 뒤 변경 목록을 확인하면 됩니다.
5. 아래 검사를 실행하고 배포합니다. 원본 해시가 확인된 옛 WAV만 정리되며, Git에 삭제로 표시된 이 중복 음원도 함께 커밋할 수 있습니다.
6. 배포 후 강력 새로고침하고 화면의 v17 및 `/health`의 `version: "17.0.0"`을 확인합니다.

```bash
npm ci
npm run verify
npm start
```

Node.js 22 또는 24를 사용합니다. 제공된 Render 설정의 빌드 명령은 `npm ci --omit=dev && npm run verify`, 시작 명령은 `npm start`입니다. 기본 모드에 Supabase 키·SQL·외부 AI 키는 필요하지 않습니다. 구형 모드 변수 `CHRONICLE_LEGACY_MODE=1`이 있으면 비워 주세요. 기존 계정 기능이 필요할 때만 `npm run start:legacy`를 사용합니다.

정확한 변경 목록과 해시는 `FILES_CHANGED_V17.txt`와 `V17_PATCH_MANIFEST.json`에 있습니다. 기존 저장소의 `.env`, 실제 저장 방, 사용자의 다른 파일은 ZIP에 포함하지 않았습니다.

## 2. 먼저 플레이하는 방법

**한 기기에서 1–4인:** ZIP 전체를 푼 뒤 Node.js로 다음 명령을 실행하고 `http://127.0.0.1:4173/`를 엽니다. 이 방식은 npm 패키지 설치 없이 실행됩니다. Windows와 macOS/Linux용 실행 파일도 함께 있습니다.

```bash
node scripts/offline-server.mjs
```

`PLAY_OFFLINE.html` 직접 실행용 번들도 제공합니다. HTML과 `public/game/`을 함께 유지해야 그림과 소리가 나옵니다. 실제 브라우저의 `file://` 실행은 이 작업 환경에서 확인하지 못했으므로, 파일 실행이나 자동 저장이 제한되면 위 로컬 서버를 사용합니다. 로컬 모드는 같은 화면을 차례로 사용하는 방식이며 LAN 서버는 아닙니다.

**각자 기기로 온라인:** 기존 프로젝트에 패치를 적용한 서버에서 방장이 이야기와 직업을 고르고 방을 만듭니다. 친구들은 6자리 코드로 들어와 직업을 고릅니다. 최대 네 명이며, 모두 연결되면 방장이 시작합니다.

## 3. 화면에서 읽을 순서

1. **직전 행동의 결과:** 판정, 사건, 실제로 바뀐 항목을 먼저 봅니다.
2. **지금 상황 / 해결할 일 / 주의할 점:** 누가 어디서 곤란한지, 이번 장면에서 무엇을 결정할지 읽습니다.
3. **이야기 본문:** 인물의 말과 주변 상황, 이미 한 선택에 따른 반응을 확인합니다.
4. **잠깐 살펴보기:** 안전한 관찰입니다. 주사위·차례·위기를 쓰지 않고 단서나 물건을 얻을 수 있습니다.
5. **정해진 행동:** 방법과 대가를 보고 하나를 고릅니다. 위험한 행동이면 판정창에서 굴립니다.

관찰을 건너뛰어도 현재 사건을 이해하는 데 필요한 설명은 본문에 들어 있습니다. 관찰로만 알 수 있는 추가 정보나 도구는 별도 보상으로 남습니다. 관찰 후 직전 결과가 바뀌어도 「직전 선택에서 이어진 상황」에서 이 장소에 온 이유를 다시 확인할 수 있습니다. 바로 앞 결과와 같은 문장은 중복 표시하지 않습니다.

## 4. D20 네 결과

| 결과 | 판정 기준 | 이야기의 처리 |
|---|---|---|
| 대성공 | 주사위 자체가 20 | 그 행동의 특별한 성과. 일반 성공과 다른 정보·협력·피해·위기·경로 중 하나 이상 적용. 운명 조각도 +1, 최대 4 |
| 성공 | 자연 1·20을 제외하고 `D20 + 보너스 ≥ 목표` | 고른 방법이 의도한 효과를 냄 |
| 실패 | 자연 1·20을 제외하고 `D20 + 보너스 < 목표` | 시도는 막히거나 대가를 치름. 사건은 다른 방식으로 진행 |
| 대실패 | 주사위 자체가 1 | 보통 실패보다 큰 부상·위기·손실 또는 다른 사건으로 진행 |

자연 1과 20은 보너스보다 우선합니다. 위험 행동의 판정창에 네 결과의 확률이 표시되며, 접힌 상세 설명을 열면 실제 결과와 변화를 미리 볼 수 있습니다. **새 판정에는 부분 성공을 사용하지 않습니다.** 이전 저장의 과거 기록에 있던 부분 성공 표시는 그대로 읽을 수 있습니다.

안전한 관찰, 이미 열린 길로 이동하기, 마지막에 어떤 가치를 선택할지 결정하기 등은 주사위 없이 진행할 수 있습니다. 모든 버튼에 억지로 위험을 붙이지 않았습니다. 첨부 화면의 시계 도시 첫 두 선택은 단순 이동에서 실제 구조 시도로 바꿔 네 판정을 적용했습니다.

능력치는 직업마다 정해져 있습니다. 별도의 능력치 굴림은 없습니다. 다른 동료 두 명까지 각각 협력 +1, 운명 조각 하나로 +3, 인물당 이야기 전체에서 한 번 「준비한 수단 사용」으로 +2를 받을 수 있습니다. 준비는 체크박스이며 회상을 직접 입력하지 않습니다. 행동을 확정해야 자원이 소비되고 미리 보기·취소에는 소비되지 않습니다.

## 5. 단서와 소지품

**단서**는 알게 된 사실의 영구 기록입니다. **소지품**은 실제로 일행이 챙긴 물건이며 함께 쓰는 가방에 들어갑니다. 각 이야기에는 실제 획득 경로와 사용 선택이 있는 물건 세 종류가 있습니다.

- 주변 관찰이나 행동의 결과로 물건을 얻습니다. 얻지 않은 물건은 가방에 생기지 않습니다.
- 물건이 쓰이는 장면에서는 가방에 「이 장면에서 쓸 수 있음」이 표시됩니다. 누르면 그 물건을 사용하는 정해진 선택의 판정창이 열립니다.
- 물건이 없어 잠긴 행동에는 무엇이 필요한지 표시합니다. 해당 물건 없이 진행하는 다른 선택도 남아 있습니다.
- 소모품은 실행 전 안내되며, 그 시도에 사용하면 성공·실패와 관계없이 소모합니다. 재사용 물건은 가방에 남습니다.
- 물건을 썼다고 이미 알아낸 단서까지 지우지 않습니다. 저장·재접속 후에도 소모 여부를 유지합니다.

예를 들어 시계 도시에서 윤에게 받은 황동 고정쐐기는 전차의 바퀴를 고정하는 데 쓸 수도 있고, 보관했다가 종탑 기계실에서 쓸 수도 있습니다. 전차에 사용했다면 나중의 쐐기 선택은 열리지 않습니다. 본문과 가방의 상태를 함께 따라가도록 구성했습니다.

## 6. 전투·사망·부활

일곱 이야기마다 전용 직업 네 개, 총 28개입니다. 기본 공격 하나와 고유 기술 하나를 사용하며, 모든 일반 결말 경로에는 이야기와 연결된 라운드 전투가 최소 한 번 있습니다. 전투 이전의 전멸은 곧바로 조기 결말로 이어집니다.

| 행동 | 대성공 | 성공 | 실패 | 대실패 |
|---|---|---|---|---|
| 기본 공격 | 적 피해 3 | 적 피해 2 | 적 피해 0 | 적 피해 0, 자신의 생명 −1 |
| 강타 기술 | 적 피해 4 | 적 피해 3 | 적 피해 0 | 적 피해 0, 자신의 생명 −1 |
| 흡수 기술 | 적 피해 3, 자신 +1 회복 | 적 피해 2, 자신 +1 회복 | 적 피해 0, 회복 없음 | 적 피해 0, 자신의 생명 −1 |

공격 목표는 11이며 주 능력치·협력 등의 보너스를 더합니다. 대실패의 자기 피해는 보호막으로 막지 못합니다. 보호·치료·약점 노출·행동 중단·격려 기술은 명시된 확정 효과를 사용합니다. 기술은 전투당 한 번이며 판정형 기술은 실패해도 사용 횟수를 소비합니다. 자세한 수치·직업별 묘사는 `CLASS_GUIDE_V17.md`에 있습니다.

살아 있는 인물들이 한 번씩 행동하면 적이 예고한 행동을 합니다. 적의 공격은 D20이 12 이상이면 예고된 피해 1이며, 플레이어의 네 가지 이야기 결과와는 별도 규칙입니다. 적을 마지막 공격으로 제압했다면 반격하지 않습니다. 전투 승리 시 생존자 생명 +1, 위기 −1, 운명 조각 +1이며 사망자는 자동으로 살아나지 않습니다.

생명은 최대 3이고 0이면 사망합니다. 사망자는 공격할 수 없지만 죽음마다 한 번 잔향으로 돕거나 개인 비밀을 공개할 수 있습니다. 생존 동료가 부활 장소에 도달해야 귀환을 시도합니다. 기본 비용은 운명 조각 1개와 위기 2칸입니다.

- 대성공: 생명 3으로 부활.
- 성공: 생명 2로 부활.
- 실패: 부활하지 못하고 기본 비용에 더해 위기 +1.
- 대실패: 부활하지 못하고 기본 비용에 더해 위기 +2.

장소마다 같은 인물에게 한 번, 인물의 성공한 부활은 이야기 전체에서 한 번입니다. **전원 사망하면 부활을 진행할 생존 동료가 없어 즉시 전멸 결말로 끝납니다.** 혼자 플레이할 때도 같습니다.

## 7. 저장과 기존 버전

v17은 v14·v15·v16의 저장을 읽습니다. v16의 내부 저장 스키마는 15였으며 v17은 17입니다. 새 저장에는 소지품·소모 기록·장면에 도착한 이유를 추가했습니다. 기존 자동 저장 키를 유지해 같은 브라우저의 이어하기도 사용할 수 있습니다.

예전 저장에는 가방이 없으므로, 해당 물건을 이미 얻었다고 판단할 수 있는 단서·사건 기록이 있는 경우에만 물건을 복원합니다. v17에서 소모한 물건은 단서가 남아 있다는 이유로 다시 만들지 않습니다. v14 일반 직업은 이야기별 대응 직업으로 옮기며, 이미 지나간 전투를 강제로 되돌리지 않습니다. v12·v13 구형 시나리오 저장은 변환하지 않습니다.

이번에는 본문과 분기를 다시 썼으므로 **새 이야기로 시작하는 것을 권장**합니다. 기존 저장의 과거 기록은 예전 문장을 그대로 보존하며, 새 규칙이 그 과거 결과를 다시 굴리지는 않습니다. 전투 중 저장은 적 생명력·라운드·사용한 기술·협력을 복구합니다. 온라인 저장은 방장만 내보낼 수 있고, 같은 인원으로 만든 새 대기실에서 가져옵니다.

기본 온라인 서버는 Supabase를 호출하지 않습니다. 메모리 운영 중 서버가 재시작하면 방이 사라질 수 있으므로 방장 브라우저 자동 복구 사본과 JSON 저장을 이용합니다. 영구 디스크가 있다면 `CHRONICLE_V17_DATA_DIR`을 실제 경로에 지정합니다. 이전 V16/V15/V14 변수도 지원합니다. 자세한 운영 설정은 `SERVER_AND_STORAGE_V17.md`를 확인합니다.

## 8. 디자인·그림·음악

v16의 잉크색·고금색 디자인, WebP 7개에 담긴 장면 28컷, BGM 35개·효과음 11개를 유지합니다. 이번 v17에서 그림이나 음원을 다시 압축하지 않았으며 미디어 바이트는 v16과 같습니다. 스토리 문장을 늘리고 화면의 읽는 순서를 바꾼 업데이트입니다.

초기 화면은 무음이며 소리를 직접 켜야 합니다. 필요한 음악만 요청하고 같은 곡은 턴마다 다시 시작하지 않습니다. 이미지는 지연 로딩하고 실패해도 글의 진행을 막지 않습니다. 실제 호스트·네트워크·기기의 지연까지 없다고 보장하지는 않습니다. 바이트 비교와 자원 제한은 `RESOURCE_REPORT_V17.json`에 기록합니다.

그림은 앞서 화풍을 조정한 AI 생성 이미지이며 사람의 수작업 원화로 표시하지 않습니다. 음원은 외부 샘플 없이 만든 합성 원곡의 96kbps 모노 MP3입니다. 제작 기록은 `ASSET_AND_DESIGN_NOTES_V17.md`에 있습니다.

| 전투 라운드·피해·기술 | `public/game/combat.js` |
| 화면·문장 표시 순서 | `public/game/app.js`, `public/game/styles.css` |
| 온라인 방·서버 판정·자동 백업 | `game-server/table-service.js` |
| 정적 미디어·HTTP 캐시 | `game-server/http-service.js` |
| 내용·규칙·실제 통신·화면 이벤트 검사 | `tests-v17/`, `scripts/qa-v17.mjs` |

`tests-v17`는 **일반 테스트 폴더**입니다. 별도로 플레이하는 게임이 아니며 `package.json`이 이 경로를 사용하므로 폴더명만 `tests`로 바꾸면 검사 명령이 끊깁니다.

이야기를 고칠 때는 `text`뿐 아니라 `summary`, `objective`, `stakes`도 맞춥니다. 위험 선택에는 `critical/success/failure/fumble` 네 결과를 모두 작성합니다. `next`는 실제 다음 장면 ID이고, `set/clues/gainItems/consumeItems` 등이 실제 효과를 결정합니다. 문장에만 물건을 얻었다고 쓰면 가방에 생기지 않습니다. 더 자세한 작성 예는 `STORY_GUIDE_V17.md`에 있습니다.

```bash
npm ci
npm run verify
npm run test:ui
npm run test:integration
npm run build:offline
```

검사 후 소스를 바꾸면 오프라인 번들도 다시 빌드합니다. 운영 서버의 `verify`에는 개발 도구가 필요한 UI 검사나 번들 재생성을 넣지 않았습니다. 검증 결과와 확인하지 못한 범위는 `VALIDATION_V17.md`에서 구분합니다.
