CHRONICLE GATE ONLINE v9.0.0 - LIVING STORY 업그레이드 패치
============================================================

이 ZIP은 전체 80MB 프로젝트를 다시 복사한 것이 아니라, 이번에 수정/추가된 파일만 담은 패치입니다.
프로젝트 최상위 폴더(기존 server.js, campaign-data.js가 있는 곳)에 그대로 덮어쓰면 됩니다.

[가장 중요한 변경]
1. 회원가입/로그인 규칙 통일
   - 비밀번호: 최소 4자, 최대 72자.
   - 4자리 비밀번호도 허용하지만 4자리로 제한하지 않습니다.
   - 로그인 화면에 표시/숨기기, 글자 수, 저장소 상태 안내를 추가했습니다.
   - 브라우저/서버의 서로 다른 비밀번호 규칙을 하나로 통일했습니다.

2. 계정 저장 DB 누락 수정
   - 새 파일: supabase/migrations/202609010002_accounts_and_progress.sql
   - cg_accounts, cg_auth_sessions, cg_endings 및 필요한 RPC를 생성합니다.
   - 운영 서버에서 Supabase를 사용할 경우 이 SQL이 적용되어 있어야 회원가입/로그인이 정상 동작합니다.

3. TRPG 자유행동 복구/강화
   - 일반 스토리와 분리 행동(병렬 스토리) 양쪽에서 직접 행동 입력을 사용할 수 있습니다.
   - 예: "경비병에게 왕가 인장을 보여주며 통과시켜 달라고 설득한다",
         "기둥 뒤에 숨어 대화 내용을 엿듣는다",
         "열쇠를 장치에 사용한다",
         "위협하지 않고 거래를 제안한다" 등.
   - 질문/순수 관찰은 장면당 최대 2회 정보 확인으로 처리할 수 있고,
     설득/협상/위협/함정/후퇴/아이템 사용처럼 상황을 바꾸는 행동은 실제 판정을 거칩니다.
   - 장면에 없는 대상에게 공격/미행/도둑질 등을 시도하면 이유를 설명하고 다른 행동을 요구합니다.

4. 선택지와 분기 수정
   - 장면당 3개로 잘리던 선택지를 일반 5개, 대면/위기/결단 6개로 확대했습니다.
   - 각 선택지의 원래 성공/실패 결과와 다음 분기를 보존합니다.
   - 막 시작 장면은 careful / empathetic / bold 3가지 접근이 실제 서로 다른 루트로 갈라집니다.
   - 비슷한 선택지만 반복되지 않도록 조사/관찰/대화/구조/잠입/강행/우회 등 의도 계열을 분산합니다.
   - 각 선택지에 기대 이득과 위험도를 표시합니다.

5. 스토리 몰입도 수정
   - 마지막 렌더 단계에서 긴 서사를 2문단으로 잘라 버리던 처리를 제거했습니다.
   - 장면에 도입-현장상황-핵심단서-압박-다음 훅이 남도록 최대 5개 문단을 유지합니다.
   - 직전 성공/실패, 확보 단서, 위치 우위, 관계 변화가 다음 장면 서술에 다시 등장합니다.
   - 실패가 곧 진행 정지가 아니라 새로운 정보/대가/우회로를 만드는 fail-forward 구조를 강화했습니다.

6. 판정 정보 UI 개선
   - 항상 정확한 DC 숫자를 먼저 보여주지 않습니다.
   - 기본적으로 쉬움/보통/어려움 같은 난이도 감각과 위험/기회를 보여주며,
     특정 통찰 정보가 있을 때만 정확한 DC를 공개할 수 있습니다.

7. 배포/검증 정리
   - 잘못된 'scripts ' (뒤 공백 포함) 폴더 때문에 npm run check가 깨지던 구조를 scripts/로 정상화했습니다.
   - npm run verify는 현재 v9 릴리스 규칙만 검증합니다.
   - 과거 버전 전용 테스트는 npm run test:legacy로 남겨 두었습니다.
   - 로컬 개발은 .chronicle-data에 계정을 저장하며 해당 폴더는 Git에서 제외됩니다.
   - 개발자 이메일 하드코딩을 제거하고 CHRONICLE_DEVELOPER_EMAILS 환경변수로 이동했습니다.

[적용 순서]
1. 기존 프로젝트를 백업합니다.
2. 이 패치 ZIP의 내용을 기존 프로젝트 최상위 폴더에 덮어씁니다.
3. Supabase를 사용 중이면 SQL Editor에서
   supabase/migrations/202609010002_accounts_and_progress.sql 을 실행합니다.
   (기존 initial migration이 아직 적용되지 않았다면 기존 migration부터 순서대로 적용합니다.)
4. 운영 환경 변수 확인:
   - SUPABASE_URL
   - SUPABASE_SECRET_KEY (서버 전용 Secret/Service Role 권한 키)
   - 필요 시 CHRONICLE_DEVELOPER_EMAILS=email1@example.com,email2@example.com
5. 로컬에서:
   npm install
   npm run verify
   npm start
6. 배포 후 브라우저에서 Ctrl+Shift+R로 강력 새로고침합니다.
   index.html/app.js/styles.css에 v9 캐시 버전을 넣었지만 오래 열린 탭은 이전 JS를 잡고 있을 수 있습니다.

[검증 결과]
- campaign/story QA: 통과
- 9개 크로니클, 총 330개 canonical story scenes 검사: 통과
- v9 release tests: 8/8 통과
- server.js / campaign-data.js / public/app.js 문법 검사: 통과
- 현재 작업 환경에서는 npm install이 네트워크/시간 제한으로 완료되지 않아 실제 HTTP 서버 기동 스모크 테스트는 수행하지 못했습니다.

[참고]
- 4자 비밀번호 허용은 요청에 맞춘 동작입니다. 실제 공개 서비스에서는 더 긴 비밀번호 사용을 권장합니다.
- 이 게임의 직접 행동 판정은 외부 LLM API에 의존하지 않는 서버 권위형 규칙 기반 해석기입니다.
  따라서 API 키 없이도 동작하고 멀티플레이 판정이 일관되게 유지됩니다.
