# Chronicle Gate v14 — 일곱 개의 이야기

이번 패치는 **이번에 첨부한 `Chronicle-Gate-Online-main(2).zip`의 v12 코드**를 기준으로 만들었습니다. v13 패치를 먼저 설치할 필요가 없습니다. 기존 저장소에 아래 파일을 같은 경로로 덮어쓰고 새 파일을 추가하면 됩니다.

## 가장 먼저 실행하기

### 한 기기로 1–4명 함께하기

1. ZIP을 완전히 압축 해제합니다. ZIP 안에서 HTML만 따로 열면 그림·음원 경로가 끊깁니다.
2. 로컬 플레이는 압축을 푼 패치 폴더에서도 실행할 수 있습니다. 온라인 배포는 기존 프로젝트에 파일을 덮어쓴 뒤 진행합니다.
3. 프로젝트 루트의 `PLAY_OFFLINE.html`을 브라우저로 엽니다.
4. 로컬 플레이에서 플레이어 이름과 직업을 고르고 이야기를 시작합니다.
5. 소리는 상단 버튼으로 직접 켭니다. 기본값은 무음입니다.

이 실행용 HTML에는 게임 코드와 시나리오가 이미 묶여 있습니다. 그림·음원은 `public/game/`의 상대 경로로 읽습니다. **외부 인터넷·계정·API 키·유료 AI 호출이 필요하지 않습니다.** PC의 Chrome/Edge/Firefox 계열을 대상으로 작성했지만 이 작업 환경에서 실제 `file://` 브라우저 시각 검증은 수행하지 못했습니다. 파일 실행이나 브라우저 자동 저장이 제한되는 환경에서는 다음 로컬 HTTP 실행을 사용하세요.

Node.js 22 또는 24가 설치되어 있으면, 추가 패키지 설치 없이 실행할 수 있습니다.

```bash
node scripts/offline-server.mjs
```

안내되는 `http://127.0.0.1:4173/`를 엽니다. Windows에서는 `START_OFFLINE_WINDOWS.bat`도 같은 서버를 실행합니다. 다른 기기와 연결하는 LAN 모드가 아니라 **현재 기기만 사용하는 로컬 모드**입니다.

### 친구가 각자 접속하는 온라인 플레이

```bash
npm ci
npm run verify
npm start
```

배포된 사이트에서 방장이 시나리오·이름·직업을 고르고 방을 만듭니다. 친구는 **6자리 초대 코드**로 참가합니다. 1–4명이 준비되면 방장이 시작합니다. 신규 모드는 회원가입 없이 사용할 수 있고, 주사위 결과는 서버에서 생성합니다.

기본 개발 서버는 `http://localhost:3000/`입니다. `npm start`에는 Express/Socket.IO 설치가 필요합니다. 반면 앞의 오프라인 HTTP 서버에는 npm 설치가 필요하지 않습니다.

## GitHub / Render 적용

1. 현재 저장소를 별도 브랜치 또는 ZIP으로 백업합니다.
2. 패치 ZIP을 풉니다. 루트에 `server.js`, `package.json`, `public/`가 보이는 구조입니다.
3. **ZIP 파일 자체를 올리는 것이 아니라, 압축을 푼 파일과 폴더를 동일한 경로에 업로드**합니다. `public/game/` 아래 그림·음원도 함께 올려야 합니다.
4. `package-lock.json`도 함께 반영합니다. 기존 `.env`나 Render의 환경변수 값을 지우지 않습니다.
5. 커밋 후 Render를 다시 배포합니다. 제공된 `render.yaml`은 Node.js 22, `npm install --omit=dev && npm run verify`, `npm start`를 사용합니다.
6. 배포 후 `/health`에 버전 `14.0.0`, 홈에 일곱 시나리오가 표시되는지 확인합니다. 브라우저를 강력 새로고침하세요.

신규 엔진에는 별도의 Supabase SQL 실행이 필요하지 않습니다. 기존 계정·DB 설정과 구버전 코드는 보존했습니다. 새 기본 화면은 v14이며, 구버전 화면은 `/legacy.html`입니다. v12/v13의 진행 중 방과 저장은 신규 시나리오 형식으로 자동 변환하지 않습니다.

## 저장과 재접속

- 로컬 플레이: 브라우저 자동 저장 + JSON 내보내기/가져오기.
- 온라인 플레이: 같은 브라우저 탭의 자리 토큰으로 재접속. 방장은 진행 중 JSON을 내보낼 수 있고 브라우저에 자동 복구 사본도 남습니다.
- 온라인 서버의 메모리 방은 **서버 재시작·무료 호스팅 절전 이후 사라질 수 있습니다.** 친구들과 긴 세션을 할 때는 JSON을 내려받으세요.
- 영구 디스크가 있는 서버라면 `CHRONICLE_V14_DATA_DIR=/var/data/chronicle-v14`처럼 실제 영구 경로를 지정할 수 있습니다. 일반 임시 디렉터리에 경로만 지정한다고 호스팅 재배포 후 보존되는 것은 아닙니다.
- 저장 JSON을 온라인에서 이어가려면 새 방의 대기실에 같은 인원을 입장시킨 뒤 방장이 가져옵니다. 현재 입장 순서대로 저장 속 인물의 자리가 연결됩니다. 홈에서 가져오면 로컬 모드로 복원합니다.
- 온라인 초대 코드는 입장용입니다. 새로고침 후 기존 자리를 회복하려면 같은 탭의 이어하기 정보를 사용하세요. 코드만으로 이미 시작된 캐릭터를 빼앗을 수 없습니다.
- 연결이 끊긴 방장은 15초 후 연결된 참가자에게 진행 권한이 넘어갑니다. 방장은 접속이 끊긴 인물의 차례를 넘길 수 있습니다. 접속자가 없는 방은 24시간 보존 정책을 사용합니다.

| 이야기 | 진행 장면 | 일반 결말 + 전멸 | 중심 갈등 |
|---|---:|---:|---|
| 막차의 일곱 번째 승객 | 12 | 3 + 1 | 귀가 장부에서 지워진 승객과 마지막 열차의 책임 |
| 유리 호텔의 도난당한 새벽 | 12 | 3 + 1 | 저장된 시간, 직원의 몫, 훔친 새벽을 돌려주는 방식 |
| 달을 파는 야시장 | 12 | 3 + 1 | 기억의 가격과 이름을 돌려받을 권리 |
| 해저 기지의 마지막 방송 | 13 | 3 + 1 | 구조 명단 밖의 사람과 목소리를 가진 생명의 동의 |
| 용의 마지막 만찬 | 12 | 3 + 1 | 먹을 수 없는 만찬, 난방과 체면, 왕국의 협상 |
| 13분 뒤에 사라지는 도시 | 13 | 3 + 1 | 멈춘 시간의 비용을 누구에게 배분할 것인가 |
| 설원에서 온 내 목소리 | 13 | 3 + 1 | 자신을 닮은 목소리와 구조·정체성에 대한 신뢰 |

총 **진행 장면 87개, 일반 결말 21개, 조기 전멸 결말 7개, 선택지 200개, 단서 61개**입니다. 한 번에 모든 장면을 읽는 구조가 아닙니다. 선택·판정·단서에 따라 일부 경로를 거치며, 조건을 만족하면 새로운 방법이 열립니다. 각 시나리오의 4개 역할에는 비밀과 목표, 조건부 개인 후일담이 있습니다.

화면에 적힌 플레이 시간은 대화를 포함한 설계 추정치이며 실제 사용자 측정값이 아닙니다. 혼자 빠르게 선택하면 훨씬 짧게 끝날 수 있고 전멸 시 즉시 마무리됩니다.

## 핵심 규칙

직업은 직접 선택하며 능력치 주사위는 없습니다. 모든 인물의 생명력은 3입니다.

| 직업 | 힘 | 민첩 | 통찰 | 교섭 |
|---|---:|---:|---:|---:|
| 수호자 | +3 | +1 | +0 | +1 |
| 길잡이 | +1 | +3 | +1 | +0 |
| 분석가 | +0 | +1 | +3 | +1 |
| 중재자 | +1 | +0 | +1 | +3 |

- 안전한 관찰: 주사위·차례·위기를 소모하지 않습니다. 같은 관찰의 단서를 중복 획득하지 않습니다.
- 위험한 행동: **D20 + 직업 + 협력 + 준비 보너스**를 목표값과 비교합니다.
- 자연 20: 대성공, 운명 토큰 1개 획득. 자연 1: 실패.
- 합계가 목표 이상: 성공. 목표보다 1–2 낮음: 대가를 치르는 성공. 그보다 낮음: 실패와 새로운 사건.
- 도덕적 결정: 주사위를 굴리지 않고 플레이어의 결정을 그대로 반영합니다.
- 동료 협력: 다른 두 명까지 각각 +1. 한 행동에 같은 사람의 중복 지원은 불가합니다.
- 운명 토큰: 일행이 2개로 시작, 최대 4개. 사용하면 +3. 비밀 공개와 자연 20으로 얻습니다.
- 회상: 각 캐릭터가 시나리오당 한 번, 어떤 준비를 했는지 8자 이상 적고 +2를 받습니다.
- 위기 게이지가 가득 차면 이후 목표가 +1 높아집니다. 시간 배경의 시나리오도 실제 초시계로 제한하지 않습니다.

## 죽음·부활·조기 결말

피해는 작성된 위험한 사건에서 발생합니다. 모든 실패에 무작위 피해가 붙는 방식이 아닙니다. 행동 확인 창에는 실제 최대 피해와 일행 전체의 피해 여부가 표시됩니다.

- 생명력 0: 사망. 남은 생존자의 차례로 진행합니다.
- 죽은 플레이어: 대화를 이어가고 비밀을 공개할 수 있으며, 죽음마다 한 번 잔향으로 동료를 지원할 수 있습니다. 직접 사건을 진행하는 행동은 못 합니다.
- 부활: 시나리오마다 3곳의 조건부 장소가 있습니다. 세계관에 맞는 표·시간·기억·재구성 기술 등으로 설명됩니다.
- 부활 시도: 살아 있는 현재 행동자가 운명 토큰 1개와 위기 2칸을 지불합니다. 성공 시 생명 2, 부분 성공 시 생명 1로 복귀합니다. 실패하면 부활하지 못하고 위기 1칸이 추가됩니다.
- 같은 장소에서 같은 인물을 위한 재시도는 불가합니다. 한 인물은 한 시나리오에서 최대 한 번 성공적으로 부활합니다. 이 제한은 저장·온라인 새 방 복원 뒤에도 유지됩니다.
- 전원 사망: 즉시 해당 이야기의 전멸 결말. 따라서 혼자 플레이하다 죽으면 부활을 수행할 동료가 없어 그 자리에서 끝납니다.
- 일부 시나리오의 위험한 지름길은 한 번의 실패로 전멸할 수 있습니다. **선택지와 확인 창에 전멸 위험을 명시하고 일반 대안을 함께 제공합니다.** 설원에서는 누적된 일행 피해로 전멸할 수 있습니다.
- 마지막 화면은 주요 선택과 역할별 후일담, 실제 생존자·희생자·부활자를 함께 보여 줍니다.

여기서 ‘여러 경우의 수’는 서로 다른 경로와 단서·상태·인물의 운명 조합을 뜻합니다. 모든 조합에 각각 완전히 별개의 장편 소설을 작성하거나, 무한히 새로운 세계를 생성하는 것은 아닙니다.

## 직접 행동 입력의 범위

API 비용 없이 작동하는 **규칙 기반 장면 해석기**입니다. 현재 인물·사물·선택의 의도·키워드를 연결해 가능한 행동으로 해석합니다. 먼저 해석된 목표, 보너스, 난도, 대가를 보여 주고 플레이어가 확인한 후 굴립니다.

현재 장면에 없는 사람을 향한 말이나 목표가 불명확한 행동은 억지로 실행하지 않고 현재 가능한 목표를 안내합니다. 선택지가 없는 완전히 새로운 세계·사건을 즉석에서 생성하는 LLM GM은 포함하지 않았습니다. 대화나 기발한 방법은 친구들과 자유롭게 연기할 수 있지만, 게임의 기계적 결과는 구현된 장면의 행동과 상태 효과에 연결됩니다.

## 그림과 소리

- 사용자의 화풍 피드백을 반영해 밝은 광택·과밀한 장식을 줄인 픽셀풍 이미지로 재제작했습니다.
- **7개 아틀라스 × 4장면 = 28컷**. 이야기가 진행되며 장 단위로 바뀝니다. 매 행동마다 새로운 그림을 실시간 생성하지는 않습니다.
- 이미지는 AI 생성 결과물이며 사람의 수작업 원화로 표시하지 않습니다. 파일은 `public/game/art/`, 생성 프롬프트는 `provenance.json`에 있습니다.
- **이야기별 5가지 분위기의 BGM 35개 + 효과음 7개**. 외부 음원 샘플 없이 합성한 원본 루프와 효과음입니다.
- 처음에는 무음이며 사용자가 켜면 장면의 분위기에 맞춰 전환됩니다. 음악과 효과음 음량은 별도로 조절합니다.
- 외부 CDN·이미지 URL·원격 음원에 의존하지 않습니다. 파일이 누락되어도 이야기를 계속 읽을 수 있는 그림 대체 화면이 있습니다.

## 직접 수정할 파일

| 목적 | 경로 |
|---|---|
| 이야기·선택·결말·사망 피해·부활 장소 | `public/game/campaigns/*.js` |
| 직업·주사위·단서·생명력·부활 규칙 | `public/game/engine.js` |
| 화면 문구·버튼·판정 창 | `public/game/app.js` |
| 화면 배치와 색상 | `public/game/styles.css` |
| 온라인/로컬 저장·전송 | `public/game/client.js` |
| 온라인 방·서버 판정·재접속 | `game-server/table-service.js` |
| 그림 | `public/game/art/*.webp` |
| 소리와 전환 | `public/game/audio/*`, `public/game/audio.js` |
| 최종 오프라인 실행 번들 재생성 | `npm run build:offline` |

시나리오 수정 후 온라인 버전은 변경된 모듈을 읽습니다. **더블클릭 오프라인 버전도 갱신하려면 `npm ci` 후 `npm run build:offline`을 실행하여 `public/offline.html`을 다시 생성**해야 합니다.

부활/사망 데이터 예시:

```js
// 기존 선택지 outcome에 추가
failure: {
  text: '사건에 맞는 실패 문장',
  next: '다음_장면_ID',
  harm: 1,       // 행동한 인물의 피해
  pressure: 1
}
// harmAll: 3은 살아 있는 일행 모두에게 3 피해. 반드시 위험을 사전에 표시하세요.
```

선택지의 `requires`는 단서/플래그로 행동을 엽니다. `set`/`unset`은 상태를 바꾸고, `clues`는 단서를 얻습니다. `callbacks`와 역할의 `epilogues`는 이미 벌어진 일을 후속 장면과 결말에서 기억합니다. 엔딩 장면의 ID를 바꾸면 모든 연결도 함께 수정해야 합니다.

## 검증과 남은 범위

`VALIDATION_V14.md`에 확인한 범위와 실행 명령을 적었습니다. 배포용 `npm run verify`는 개발 의존성 없이 콘텐츠·엔진·시나리오 검사를 수행합니다. 실제 통신·UI 동작 검사는 개발 의존성을 설치한 후 별도로 실행할 수 있습니다.

이번 결과물은 친구들과 테스트하고 계속 발전시킬 수 있는 실행 가능한 소스 빌드입니다. 실제 친구들의 여러 세션 평가, 장시간 서버 운영, 실제 PC/모바일 브라우저의 화면과 오디오 재생에 대한 최종 확인까지 마친 상용 출시 보증은 아닙니다.
