# Chronicle Gate v16 — 연대기 디자인과 가벼운 서버

**7개 이야기마다 전용 직업 4개, 총 28개 직업을 선택합니다. 모든 직업은 기본 공격 하나와 고유 기술 하나를 갖습니다.** 능력치 굴림은 없으며, 각 이야기의 중간에 실제 라운드 전투가 한 번 들어갑니다. 전투 이후에는 원래의 분기, 비밀, 사망·부활과 여러 결말이 이어집니다.

v16에서는 화면을 짙은 잉크색·고금색의 연대기로 다시 구성했습니다. 홈의 큰 제목과 아치형 장면 창, 기록집 표지, 대기실과 전투 화면에 같은 디자인을 적용했습니다. 이야기·직업·전투 규칙과 장면 그림은 v15와 동일하며, 음원은 96kbps MP3로 제공합니다. 서버의 자세한 절약 방식과 제한은 `SERVER_AND_STORAGE_V16.md`를 확인하세요.

이 ZIP은 사용자가 첨부한 `Chronicle-Gate-Online-main(2).zip`의 코드를 기준으로 만든 **누적 수정 패치**입니다. v14 또는 v15를 적용한 저장소에도 같은 경로로 덮어쓸 수 있습니다. 온라인 서버 전체를 새로 담은 독립 프로젝트는 아니므로, 온라인 배포는 기존 저장소 위에 적용합니다. 한 기기 로컬 플레이에 필요한 새 게임 코드·그림·음원은 패치에 함께 들어 있습니다.

## 1. GitHub에 적용하기

1. 현재 작업은 별도 브랜치나 백업에 보관합니다.
2. ZIP을 완전히 풉니다. 압축을 푼 루트에는 `server.js`, `package.json`, `public/`, `game-server/`, `tests-v16/` 등이 있어야 합니다.
3. **ZIP 자체를 올리지 말고 압축 안의 파일들을 저장소의 같은 경로에 덮어씁니다.** 기존 `public/` 안에 다시 `public/`을 중첩하지 않습니다.
4. 새 파일과 수정 파일을 함께 커밋합니다. `package-lock.json`과 `public/game/`의 그림·소리도 포함합니다. GitHub Desktop에서는 저장소 폴더에 복사한 뒤 변경 목록을 확인하고 커밋하면 됩니다. 웹 업로드의 파일 수 제한을 만나면 `public/`와 나머지 파일을 나누어 올립니다.
5. 가능하면 로컬에서 `npm ci`와 `npm run verify`를 실행합니다. 검사는 예전 원본 WAV 중 정상 MP3로 교체된 파일만 정리합니다. GitHub 변경 목록에 표시되는 이 WAV 삭제도 함께 커밋하면 저장소와 다음 배포에 중복 음원이 남지 않습니다. 직접 수정한 WAV는 삭제하지 않습니다.
6. 배포 후 브라우저를 강력 새로고침하고 `/health`의 `version: "15.0.0"` 및 화면 하단 v16 표시를 확인합니다.

권장 개발 실행:

```bash
npm ci
npm run verify
npm start
```

Node.js 22 또는 24를 사용합니다. 제공된 `render.yaml`은 `npm ci --omit=dev && npm run verify` 후 `npm start`로 실행합니다. `verify`에는 개발 의존성이 필요한 브라우저 DOM 테스트나 번들 빌드를 넣지 않았습니다. 기본 실행에는 Supabase 키와 SQL이 필요하지 않습니다. 기존 호스트의 `SUPABASE_*` 변수가 남아 있어도 새 기본 서버에서는 사용하지 않습니다. 현재 배포 설정에 `CHRONICLE_LEGACY_MODE=1`이 있거나 시작 명령이 `start:legacy`이면 구형 모드로 실행되므로, 새 모드를 사용할 때는 시작 명령을 `npm start`로 설정하고 해당 모드 변수를 비워 주세요.

현재 기본 화면과 서버는 v16입니다. 구형 서버는 `legacy-server.js`에 보존했습니다. 구형 계정·게임 기능이 필요한 운영자는 `npm run start:legacy`로 실행한 뒤 `/legacy.html`을 사용합니다. 기본 서버의 `/legacy.html`에는 별도 실행 안내만 나오며 구형 계정 API는 열리지 않습니다. 원본에서 패치에 포함되지 않은 파일은 기존 저장소에 남겨 둡니다. 전체 변경 파일과 해시는 `FILES_CHANGED_V16.txt`, `V16_PATCH_MANIFEST.json`에서 확인할 수 있습니다.

## 2. 설치 없이 한 기기에서 먼저 플레이하기

ZIP을 완전히 푼 다음 `PLAY_OFFLINE.html`을 엽니다. 실행용 HTML에 코드가 이미 묶여 있으며 그림·음원은 같은 폴더 아래 `public/game/`에서 읽습니다. HTML 한 파일만 다른 위치로 옮기면 미디어 경로가 끊깁니다.

이 환경에서는 실제 브라우저의 파일 실행을 시각적으로 검증하지 못했습니다. 파일 실행이나 자동 저장이 제한되는 브라우저에서는 Node.js가 설치된 PC에서 다음 로컬 서버를 사용합니다. 이 방법에는 npm 패키지 설치가 필요하지 않습니다.

```bash
node scripts/offline-server.mjs
```

`http://127.0.0.1:4173/`를 열면 됩니다. Windows는 `START_OFFLINE_WINDOWS.bat`, macOS/Linux는 `START_OFFLINE_MAC_LINUX.sh`도 제공합니다. 로컬 모드는 같은 화면을 차례로 사용하는 1–4인 방식이며 LAN 접속 서버는 아닙니다.

친구가 각자의 기기로 접속하려면 기존 프로젝트에 패치를 적용해 온라인으로 실행합니다. 방장이 이야기를 고르고 방을 만들면 친구가 6자리 코드로 참가합니다. 참가자는 방에 들어온 뒤 해당 이야기의 직업을 고릅니다. 모두 준비되면 방장이 시작합니다.

전투는 각 시나리오의 모든 일반 결말 경로가 통과하는 중간 장면에 연결되어 있습니다. 전투 전에 전원이 사망해 조기 종료하는 경우까지 억지로 전투를 진행시키지는 않습니다. v16 신규 게임의 일반 결말에는 해당 전투의 승리가 필요합니다.

직업별 기본 공격·기술·능력치 전체 목록은 `CLASS_GUIDE_V16.md`에 있습니다. 기술의 효과는 강타, 흡수 회복, 약점 노출, 행동 중단, 보호, 치료, 격려의 일곱 규칙 유형으로 구성하고, 각 직업의 장비와 세계관에 맞는 별도 이름과 행동 묘사를 붙였습니다. 28개가 모두 완전히 별개의 수학 규칙을 쓰는 것은 아닙니다.

직업은 자유롭게 고르며 같은 직업을 여러 명이 선택할 수도 있습니다. 개인 비밀과 목표는 참가 순서에 따른 네 역할 카드로, 전투 직업과는 별도로 부여됩니다. 대기실에서 시나리오를 바꾸면 각 참가자의 기존 직업 위치를 새 이야기의 같은 위치로 옮기며, 시작 전에 다시 선택할 수 있습니다.

## 4. 전투는 두 행동으로 진행합니다

화면에서 적의 생명력, 이번 라운드의 적 행동, 공격 대상, 피해를 먼저 확인합니다. 내 차례에는 **기본 공격** 또는 **고유 기술**을 선택합니다. 아군에게 쓰는 기술에만 대상 선택기가 표시됩니다.

### 기본 공격

- 횟수 제한 없이 자기 차례에 사용할 수 있습니다.
- D20 + 직업의 주 능력치 + 협력·준비 보너스를 목표 11과 비교합니다.
- 합계 11 이상: 피해 2. 합계 9–10: 부분 명중으로 피해 1. 그 미만: 빗나감, 피해 0.
- 자연 1은 항상 빗나가고, 자연 20은 대성공으로 피해 3 및 운명 조각 1개를 얻습니다.
- 직업의 공격 보너스는 기본 +3입니다. 이야기의 조사·교섭에서는 해당 행동에 맞는 다른 능력치를 사용합니다.

### 고유 기술

- 인물마다 **전투당 한 번**, 자기 차례를 사용합니다. 판정형 기술은 실패해도 사용 횟수를 소모합니다.
- 강타·흡수는 주사위 판정을 합니다. 나머지 지원 기술은 정해진 효과가 확정 적용됩니다.
- 보호·치료 대상에는 자신도 포함됩니다. 사망한 동료에게 쓰거나 전투 중 부활시키지는 못합니다.
- 보호막은 최대 3이며 실제 막은 피해만큼 줄어듭니다. 전투가 끝나면 남은 보호막·격려·약점 등 전투 상태는 사라집니다.
- 행동 중단을 겹쳐 써도 미래 적 행동 여러 번을 예약 취소하지 않습니다. 격려 +2도 중첩되지 않으며 지원 기술에는 소비되지 않습니다. 약점은 다음 두 번의 명중에만 피해 +1을 더합니다.

### 라운드와 적의 반격

생존자들이 한 번씩 행동하면 적이 예고한 행동을 판정합니다. 대상은 라운드 시작에 고정되며, 치료를 받았다고 다른 사람으로 몰래 바뀌지 않습니다. 적 D20이 12 이상이면 예고된 피해 1을 줍니다. 전체 공격은 대상마다 따로 굴립니다. 마지막 공격으로 적을 제압했다면 추가 반격은 없습니다.

전투 진입 시 살아 있는 일행 수에 따라 적의 최대 생명력이 6/10/14/18로 조정됩니다. 인물이 죽었다고 적의 생명력이 중간에 줄어들지는 않습니다. 접속이 끊긴 인물은 방장이 차례를 넘길 수 있으며, 그 인물은 방어막 1을 얻고 라운드의 행동을 마칩니다. 연결된 인물은 양보를 반복해 적의 공격을 피할 수 없습니다.

동료 협력은 다른 두 명까지 각각 +1입니다. 운명 조각 하나로 판정 +3, 인물당 이야기 전체에서 한 번의 회상으로 +2를 받을 수 있습니다. 이런 추가 선택은 화면의 접힌 보너스 항목에 들어 있습니다.

승리하면 살아 있는 일행이 생명 1씩 회복하고 위기 −1, 운명 조각 +1을 얻습니다. 같은 전투의 보상을 재접속으로 다시 받을 수 없습니다. 사건의 승리 기록을 남기고 원래 장면의 조사·선택지가 열립니다.

## 5. 죽음, 부활, 여러 결말

생명력은 3으로 시작합니다. 전투와 위험한 이야기 선택의 피해가 같은 생명력에 누적되며 0이면 사망합니다. 사망자는 공격하지 못하지만 비밀을 공개하거나 죽음마다 한 번 잔향으로 동료의 판정을 도울 수 있습니다.

살아 있는 동료가 이야기를 이어가 부활 장소에 도달하면 귀환을 시도할 수 있습니다. 각 이야기에는 세계관에 맞는 부활 장소가 세 곳 있습니다. 기본 비용은 운명 조각 1개와 위기 2칸이며, 성공 시 생명 2, 부분 성공 시 생명 1로 돌아옵니다. 실패 시 부활하지 못하고 위기가 1 더 늘어납니다. 한 장소에서 같은 인물에게 한 번만 시도할 수 있고, 한 인물의 성공한 부활은 이야기 전체에서 최대 한 번입니다.

전투 승리는 죽은 동료를 자동으로 살리지 않습니다. 전원이 사망하면 그 즉시 해당 이야기의 조기 전멸 결말로 끝납니다. 혼자 플레이하다 죽은 경우에도 귀환을 수행할 생존 동료가 없어 종료됩니다.

이야기는 진행 장면 87개, 일반 결말 21개, 조기 전멸 결말 7개, 선택지 200개, 단서 61개로 구성되어 있습니다. 주요 선택과 단서, 개인 비밀, 실제 생존자·사망자·부활자의 기록에 따라 후일담이 달라집니다. 이 숫자는 집필된 기본 결말의 수이며 상태 조합을 별개의 소설 수로 세지 않았습니다.

## 6. 저장 호환성과 재접속

**새 전투를 모두 경험하려면 v16에서 새 이야기를 시작하세요.**

- v16 저장은 적 생명력, 라운드, 예고 대상, 행동을 마친 사람, 사용한 기술, 보호막·격려·약점, 미사용 협력과 직전 적 판정을 함께 보존합니다.
- v14 저장은 네 일반 직업을 해당 이야기의 네 전용 직업으로 옮깁니다. 기존 순서 `수호자/길잡이/분석가/중재자`가 새 직업의 1/2/3/4번 위치에 대응합니다.
- v14에서 이미 방문한 전투 배치 장면은 통과한 것으로 처리해 진행을 되돌리지 않습니다. 아직 방문하지 않은 전투 장면은 이후 도착할 때 진행합니다.
- v12/v13 구형 시나리오 저장은 신규 엔진으로 자동 변환하지 않습니다.
- 같은 브라우저의 v14 자동 저장을 이어받도록 저장 키를 유지했습니다. 이름과 음량 설정도 유지합니다. 소리는 매 방문마다 사용자가 직접 켭니다.
- 온라인 저장 파일은 방장만 내보낼 수 있습니다. 다른 방에서 이어가려면 새 대기실에 같은 인원을 모은 뒤 방장이 가져옵니다. 참가 순서에 따라 캐릭터와 전투 대상·협력의 연결도 함께 바뀝니다.
- 메모리로 운영하는 온라인 방은 서버 재시작 후 사라질 수 있습니다. 방장은 JSON 저장과 브라우저 자동 복구 사본을 사용할 수 있습니다.
- 영구 디스크가 있다면 `CHRONICLE_V16_DATA_DIR`을 실제 영구 경로로 지정합니다. 기존 `CHRONICLE_V15_DATA_DIR`와 `CHRONICLE_V14_DATA_DIR`도 지원하므로 저장 방을 유지하려면 기존과 같은 디렉터리를 사용합니다. 일반 임시 디렉터리에 변수만 지정해도 재배포 후 보존되는 것은 아닙니다.
- 온라인 자리 복원에는 같은 탭에 남은 자리 토큰이 필요합니다. 초대 코드는 새 참가용이며 이미 시작된 캐릭터를 가져오는 비밀번호가 아닙니다. 연결된 참가자가 없는 방은 마지막 활동 후 기본 24시간이 지나면 정리됩니다. 채팅은 최근 30개와 30분 범위만 유지하며 게임의 진행 상태와는 별개입니다. 방장은 진행 상태가 바뀔 때마다 개인 checkpoint를 받아 브라우저 복구 사본을 갱신합니다. 이 사본은 계정 기반 클라우드 저장이 아니므로 중요한 진행은 JSON 파일로도 내려받으세요.

## 7. 그림·음악·효과음

그림은 v14에서 화풍을 조정한 **7개 아틀라스, 총 28컷**을 사용하며 장면의 장에 맞춰 바뀝니다. 이번 패치에서 새 전투 전용 그림 7장을 추가한 것은 아닙니다. 제한된 명암과 무광 색감의 픽셀풍이며 AI로 생성한 이미지를 사람의 수작업 원화로 표시하지 않습니다. 생성 기록은 `public/game/art/provenance.json`에 있습니다.

이야기별 5가지 분위기의 **BGM 35개**를 포함합니다. 전투 중에는 해당 이야기의 위험 음악으로 바뀌고, 공격·기술·피격·승리용 소리를 추가해 **효과음은 총 11개**입니다. 음악과 효과음은 각각 음량을 조절할 수 있습니다. 음악은 외부 샘플 없이 합성한 같은 원곡이며 게임 실행에는 합성·압축 프로그램이 필요하지 않습니다. v16은 46개를 전부 96kbps MP3로 변환했습니다. 원본과 같은 22,050Hz·모노를 유지하지만 MP3는 손실 압축이므로 파형이나 청감이 완전히 동일하다고 보장하지 않습니다. 음원 파일만 비교하면 36,953,028 → 10,108,567바이트로 72.64% 줄었습니다. 초기 화면은 무음이며, 소리를 켠 뒤 필요한 곡과 효과음만 요청합니다. 같은 곡은 장면 갱신 때 재시작하지 않습니다.

외부 이미지 CDN이나 음원 URL을 사용하지 않습니다. 파일을 배포할 때 `public/game/art/`와 `public/game/audio/`를 함께 올립니다.

`tests-v16`는 자동 검사 코드를 모은 일반 테스트 폴더입니다. 별도의 실행 프로그램이나 게임 버전 두 개를 설치하는 폴더가 아닙니다. `package.json`에 등록된 `npm test`가 이 폴더를 실행하므로 임의로 폴더 이름만 바꾸면 검사 경로가 끊깁니다.

직업을 고칠 때 `combat-data.js`의 `profession(...)` 호출에서 이름과 공격·기술 문구를 바꿉니다. 능력의 `type`은 구현된 일곱 값 가운데 하나를 사용합니다. 새 효과 유형을 만들려면 `combat.js`의 판정·효과 적용과 관련 검사를 함께 고칩니다. 단순히 기술 설명에 수치를 적는 것만으로 엔진 효과가 바뀌지는 않습니다.

소스를 고친 뒤에는 다음 명령으로 검사하고 오프라인 파일도 갱신합니다.

```bash
npm ci
npm run verify
npm run test:ui
npm run test:integration
npm run build:offline
```

음악 전체를 다시 만들 경우 `npm run build:audio`를 실행합니다. 이 개발 작업에만 Python 3·NumPy·ffmpeg·ffprobe가 필요합니다. 원본 WAV를 합성한 뒤 MP3로 변환하고, 변환 성공과 해시가 확인된 WAV만 정리합니다. 변환은 배포 전 한 번 수행하며 플레이 중에는 실행하지 않습니다. 그림·음원을 바꿀 때에는 `app.js`와 `audio.js`의 해당 미디어 버전 쿼리도 갱신하고, `game-server/http-service.js`의 불변 캐시 버전을 함께 갱신합니다.

## 9. 구현과 검증의 범위

자유 입력은 현재 장면의 대상·행동·키워드를 읽는 **규칙 기반 해석기**입니다. 외부 LLM/API 키 없이 실행되며 새로운 장편 세계를 무한 생성하는 AI GM은 포함하지 않습니다. 전투에서는 기본 공격과 고유 기술 버튼으로 행동합니다.

규칙·화면 이벤트·실제 Socket.IO 통신·HTTP 배포 검사는 수행했습니다. 실제 브라우저의 시각적 배치, 각종 휴대전화, 사용자 Render 계정 배포, 친구 네 명의 장시간 플레이를 완료했다는 뜻은 아닙니다. 판매 준비가 모두 검증된 최종 상용판으로 표시하지 않습니다. 실행 결과와 한계는 `VALIDATION_V16.md`를 확인하세요.
